# 后训练学习与复现规划

这份规划围绕两个目标展开：通过公开项目补齐后训练的实践能力，以及从可复现的失败现象中寻找研究问题。当前先选择一个项目，完成从数据、训练到独立评估的完整流程，再决定是否扩大为论文课题。

整理日期：2026 年 10 月 8 日。依据：[ChatGPT 规划原文](https://github.com/Ricardo-Ssy/Agent-post-train/blob/3fab84168cfd253647d5e8a5e87545c191801c03/notes/planning/chatgpt-plan-original.txt)。以下优先级沿用原规划的建议，不代表岗位数量、发表概率或已经确定的个人选择；项目开放状态和资源要求尚未重新核验。

## 方向选择

| 目标 | 优先考虑 | 第一个落点 | 希望得到的成果 |
| --- | --- | --- | --- |
| 求职与后训练实践 | 工具调用或搜索 Agent，二选一 | ToolRL 或 Search-R1 | 数据处理、训练、评估、失败分析与部署测试的完整项目 |
| 论文问题探索 | Agent 长期记忆 | LongMemEval 上的记忆更新与失效分析 | 一个稳定的失败现象和最简单的修复对照 |
| 算力有限或不稳定 | 大模型路由 | 缓存数据上的简单路由与 RouteLLM | 质量、成本和分布迁移的可复现实验 |
| 延续脑电积累 | EEG 基础模型适配 | CBraMod 或 REVE 的已有模型 | 低标注、跨被试或通道缺失条件下的适配分析 |
| 后续交叉拓展 | 神经信号分析 Agent | NS-Copilot | 在严格数据隔离下比较分析与决策能力 |
| 保留探索 | EEG 转文本 | 先验证模型是否利用真实神经信号 | 信号依赖性与自由生成评估 |

**执行原则：同一阶段只推进一条主要路线。** 记忆、路由和脑电方向先作为候选，不同时开启多套训练工程。研究问题均为待验证假设，需要通过基线实验和相关工作核查判断是否值得继续。

## 工具调用与 Agent 后训练

**适合目标：** 补齐训练侧能力，理解工具数据、采样轨迹、奖励设计和任务执行之间的关系。

**学习顺序：** 公开工具数据 → SFT 基线 → ToolRL 强化学习基线 → τ 系列有状态环境 → 失败分析 → 针对性改进。

**候选问题：** 工具执行出现可恢复错误时，小模型能否有效修复，减少重复调用、盲目重试和过早放弃？

| 实验要素 | 第一版安排 |
| --- | --- |
| 场景 | 在沙箱中控制缺失字段、工具暂时不可用、状态变化等扰动 |
| 对照 | 普通 SFT、原始 RL、加入修复策略训练的模型 |
| 主要指标 | 正常成功率、扰动恢复率、额外调用次数、未见工具或故障类型上的迁移效果 |
| 关键边界 | 区分可修复、应停止和应询问用户的情况 |

ToolRL 的静态工具学习数据与 τ 环境的多轮执行轨迹属于不同设置。接入后者需要独立完成环境适配、轨迹采集和执行评估。只改奖励权重或加长度惩罚，不能直接当作研究贡献；应先找到明确的失败机制。

## 搜索 Agent 与可靠性安全

**适合目标：** 学习搜索交互式 RL，再聚焦证据使用或一个具体的安全问题。

**学习顺序：** 普通 RAG → 固定本地语料与检索器 → Search-R1 → 搜索与证据错误分析 → 选择一个问题 → 针对性训练。

候选切口二选一，第一轮不同时加入多跳推理、成本、幻觉、安全和记忆：

| 切口 | 核心问题 | 评估约束 |
| --- | --- | --- |
| 冲突证据 | 检索结果正确、过时或互相矛盾时，何时继续搜索、回答或承认证据不足？ | 控制搜索预算和可用证据，排除“只是查得更多”的解释 |
| 间接提示注入 | 工具返回内容夹带恶意指令时，能否继续完成正常任务？ | 固定威胁模型，比较干净任务效用与受攻击表现，关注未见攻击 |

SafeSearch 可作为有害请求安全分支的候选，AgentDojo 可作为工具内容提示注入分支的候选。两者任务定义不同，不能混用数据后报告一个笼统的“安全分数”。安全提升也需结合正常任务效用与拒答情况判断。

正式运行前核对检索资源、评判器配置和外部 API 成本。先固定可复现的检索环境，再考虑实时网页搜索。

## Agent 长期记忆与经验学习

**适合目标：** 用较小实验验证论文问题；第一步固定回答模型，研究记忆操作本身。

**学习顺序：** LongMemEval 与基础记忆方案 → 更新错误分析 → 最简单的修复对照 → 有稳定现象后再研究 Mem-α 等学习式记忆策略。

**候选问题：** 经验被更新或纠正后，如何兼顾当前知识的正确性、仍有效旧知识的保留和历史信息的可追溯性？

例如某工具过去使用参数 A，更新后使用参数 B。系统既要回答“现在怎么调用”，也要解释“过去为什么失败”。

| 实验要素 | 第一版安排 |
| --- | --- |
| 固定条件 | 同一个回答模型、相同任务与可比较的存储和检索预算 |
| 对照方案 | 原始记录检索、摘要记忆、普通覆盖更新、带来源和有效时间的更新策略 |
| 主要指标 | 更新后准确率、仍有效旧知识的保留率、历史问题回答能力、存储量和检索成本 |
| 数据划分 | 训练与最终测试的历史分离，避免随机拆分高度相关的问答对 |
| 继续条件 | 找到稳定、可解释的更新错误，并证明改进不是额外上下文或预算带来的 |

LongMemEval 的测试题不能同时用于训练和证明泛化。先验证哪些更新操作会造成信息丢失，再选择记忆结构；不预设图结构一定有效。多模态轨迹和人类经验作为后续拓展。

相关工作候选包括 Mem-α、LazyMem、LongMemEval-V2 和 Memory-R1。是否作为训练基线，需要先核对代码、数据和硬件要求，不能仅根据参数量判断复现成本。

## 大模型路由与预算分配

**适合目标：** 在算力有限时，用较小的决策模型完成训练、泛化与成本评估。

**学习顺序：** 缓存数据上的简单路由 → RouteLLM 与 GraphRouter 对照 → 独立任务分布迁移 → 校准或受约束决策 → 小规模真实调用验证。

**候选问题：** 用户任务分布发生变化后，路由器能否识别自身的不可靠性，并在质量约束下调整模型选择？

| 实验要素 | 第一版安排 |
| --- | --- |
| 数据起点 | RouterBench 等缓存回答与性能记录 |
| 迁移设置 | 例如从通用问答迁移到代码或长文档任务，明确训练与测试任务边界 |
| 主要指标 | 回答质量、成本、低质量回答率、最差任务组表现、路由开销 |
| 真实验证 | 在固定版本的小规模模型池上补充实际调用 |

历史模型池与成本仅支持对应设置下的结论，不能直接代表当前部署价格。GraphRouter 已被原规划列为图路由和新模型泛化的相关工作，这些概念本身不直接构成新意。

## EEG 基础模型适配

**适合目标：** 延续 EEG 数据处理与跨被试评估经验，学习预训练表示的适配和泛化。

**学习顺序：** CBraMod 或 REVE 已有模型 → 单一任务处理与评估 → 冻结编码器和线性头 → 参数高效适配与完整微调 → 低标注或通道缺失分析。需要语言接口时，再考虑 NeuroLM。

**候选问题：** 新被试标注很少、通道不完整时，预训练 EEG 模型如何可靠适配，何时会失效？

| 实验要素 | 第一版安排 |
| --- | --- |
| 数据起点 | PhysioNet EEG Motor Movement/Imagery Dataset，或已有合法访问权限的数据 |
| 对照 | 冻结编码器加线性头、参数高效适配、完整微调 |
| 评估维度 | 按被试或会话划分，比较标注预算、受控通道缺失和真实配置差异 |
| 泛化验证 | 在条件允许时，增加不同数据来源的验证 |

避免相邻信号切片跨越训练与测试划分；解释 PhysioNet 的 T1/T2 标签时要结合实验 run。通道兼容性已有相关研究，需要将问题缩到具体的低标注预算、可靠性或跨来源泛化条件。

CBraMod、REVE 与自然语言大模型的任务定位不同；NeuroLM 的神经信号与语言接口也不能直接等同于任意文本解码。优先适配已有模型，完整预训练另行评估资源。

## 神经信号分析 Agent

**适合目标：** 后续连接 EEG 与 Agent 两类经验，研究分析过程中的规划、决策和验证。

**候选起点：** NS-Copilot。原规划涉及的数据入口包括 OpenNeuro `ds004504`、`ds004584`；其中不同任务的信号类型需要单独确认，不统一视为 EEG。

**候选问题：** 在有限预算下，Agent 能否选择科学上有效的分析流程，避免数据泄漏和反复试测试集？

| 实验要素 | 第一版安排 |
| --- | --- |
| 数据访问 | Agent 仅访问训练集和开发集，最终测试集由外部评测器保管 |
| 对照 | 固定分析流水线、普通代码 Agent、待验证方法 |
| 主要指标 | 独立测试性能、协议违规率、实验成本、复现一致性，并记录代码跑通率 |
| 研究落点 | 可泛化的模型选择、预处理决策、工具错误修复或结果验证机制 |

增加 Agent 角色或集成更多工具只能说明工程变化。是否形成研究贡献，取决于决策机制及其在独立任务上的效果。

## EEG 转文本的前置验证

原规划将 ZuCo、COFETT 列为阅读候选，并把这一方向放在保留探索的位置。阅读 EEG、受控想象和自由表达解码的采集范式与任务定义需要分别处理。

在比较模型结构前，先确认模型是否利用了神经信号。至少对照真实 EEG、打乱配对、统计性质匹配的噪声和无 EEG 输入；生成评估不提供真实前文 token，并区分未见句子、未见会话和未见被试。

只有信号依赖性得到支持后，再讨论更强语言模型或生成指标的提升。

## 分阶段执行

以下将原规划转为执行清单。尚未确定可用算力和每周投入，因此先按完成条件推进，不设置未经确认的周数。

| 阶段 | 要完成的工作 | 交付物与进入下一阶段的条件 |
| --- | --- | --- |
| 选择项目 | 确定首要目标，从相应路线选一个起点，核对资源和开放状态 | 一页项目说明，写清目标、数据、设备与预算 |
| 固定基线 | 固定代码、模型、数据版本，读通主流程 | 环境记录、关键代码笔记与可执行命令 |
| 最小运行 | 用少量样本验证数据到输出的链路 | 日志与结果，注明距完整复现还有哪些差异 |
| 独立评估 | 使用固定评估协议跑基线，归类失败案例 | 基线指标、失败案例和评估脚本或命令 |
| 单点改进 | 针对一个稳定失败问题加入最简单的修复 | 相同条件下的对照结果与资源开销 |
| 判断去留 | 在独立数据或任务设置中检查效果，核查相关工作 | 继续、缩小范围或结束该假设的结论与依据 |

对于求职主线，训练项目还应能解释数据处理、SFT 与 RL 的关系、采样、奖励和训练稳定性，并完成部署测试。对于记忆、路由等路线，按任务需要选择训练环节，不机械套用完整 RL 流程。
